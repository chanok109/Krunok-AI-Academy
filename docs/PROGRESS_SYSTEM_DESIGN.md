# ออกแบบระบบบันทึกความก้าวหน้าของนักเรียน

สถานะ: ร่างเพื่อตัดสินใจ · 2026-11-16

## 1. สภาพปัจจุบัน (จากการอ่านโค้ด)

| เรื่อง | ตอนนี้เป็นอย่างไร | ผลกระทบ |
|---|---|---|
| ที่เก็บความก้าวหน้า | `api.loadProgress/saveProgress` เขียนลง `localStorage` อย่างเดียว ([apiService.js](../src/services/apiService.js)) | เปลี่ยนเครื่อง/ล้างเบราว์เซอร์ = ข้อมูลหาย และครูมองไม่เห็นข้อมูลนักเรียนเลย |
| การยืนยันตัวตนกับเซิร์ฟเวอร์ | ทุก action ใน `doPost` (ยกเว้น `login`) เรียก `authenticateAndResolveUser_` ซึ่งต้องใช้ Google `idToken` | ผู้ใช้ที่เข้าระบบด้วยรหัสประจำตัว (`authProvider: "sheets"` ค่าเริ่มต้น) ไม่มี idToken จึงเรียก API ใดๆ ไม่ผ่าน รวมถึง `quiz/submit` ที่ `QuizRunner` เรียกอยู่ |
| `login` ฝั่งเซิร์ฟเวอร์ | `loginWithUsernamePassword_` ใช้ตัวแปร `classroom` ที่ไม่ได้ประกาศ ([Code.gs](../backend/Code.gs) ท้ายไฟล์) | เกิด ReferenceError ทุกครั้ง ไคลเอนต์จึงตกไปใช้ทางสำรองเสมอ |
| ทางสำรองตอน login | เบราว์เซอร์ดึงชีต `Users` ทั้งแผ่นผ่าน gviz แล้วเทียบรหัสผ่านเอง | **ช่องโหว่ร้ายแรง:** ชีตต้องเปิดสาธารณะ และ Sheet ID อยู่ในไฟล์ JS ใครก็โหลดรหัสผ่านของนักเรียนทุกคนได้ |
| หน้าครู | `TeacherDashboard` ใช้ข้อมูลตัวอย่าง เมื่อ `teacher/getRoster` ไม่ตอบ และคำนวณ % หน่วยแบบประมาณ (`quiz > 0 ? 100 : 50`) | ตัวเลขที่ครูเห็นไม่ใช่ข้อมูลจริง |
| ชีต `Progress` | ออกแบบเป็น 1 แถวต่อ 1 บทเรียน มีแค่ `saveLesson` ที่เขียนลง แต่ UI ไม่เคยเรียก | ไม่มีข้อมูลกิจกรรม คะแนนกิจกรรม การสะท้อนคิด |

ข้อดีที่ใช้ต่อได้: โครงสร้าง progress ฝั่งไคลเอนต์ (`emptyProgress`, `normalizeProgress`, `buildSummary` ใน [quizService.js](../src/services/quizService.js)) ครบและผ่านการ normalize แล้ว ส่วนการตรวจข้อสอบที่เซิร์ฟเวอร์ (`gradeQuizOnServer_` + ชีต `QuizAttempts`) ก็พร้อมใช้งาน

## 2. เป้าหมาย

1. ความก้าวหน้าไม่หายเมื่อเปลี่ยนเครื่อง และทำงานต่อได้ตอนเน็ตหลุด
2. ครูเห็นความก้าวหน้าจริงรายคน/รายห้อง
3. คะแนนแบบทดสอบเชื่อถือได้ (ตรวจที่เซิร์ฟเวอร์ นักเรียนแก้เองไม่ได้)
4. รหัสผ่านไม่หลุดออกจากเซิร์ฟเวอร์
5. แก้โค้ดให้น้อยที่สุด ใช้ Apps Script + Google Sheets เดิม

ไม่ทำในรอบนี้: real-time, ประวัติการเปลี่ยนแปลงทุกคลิก, ระบบแจ้งเตือนผู้ปกครอง

## 3. แนวทางที่เลือก: “สแนปช็อตต่อคน + คะแนนสอบแยกตาราง”

```
เบราว์เซอร์นักเรียน                      Apps Script                     Google Sheets
┌─────────────────────┐   progress/sync   ┌──────────────────┐   1 แถว/คน   ┌───────────────────┐
│ AppContext.commit()  │ ───────────────▶ │ ตรวจ sessionToken │ ───────────▶ │ ProgressSnapshots │
│  └ localStorage      │ ◀─────────────── │ merge + บันทึก     │              └───────────────────┘
│    (แคช + คิวออฟไลน์) │   progress ล่าสุด  └──────────────────┘
│ QuizRunner           │   quiz/submit     ตรวจคะแนนที่เซิร์ฟเวอร์ ──────────▶ QuizAttempts (มีอยู่แล้ว)
└─────────────────────┘
หน้าครู ── teacher/getRoster ──▶ อ่าน ProgressSnapshots + QuizAttempts ──▶ สรุปด้วยกติกาเดียวกับ buildSummary
```

**เหตุผล:** ไคลเอนต์มีโครงสร้าง progress ที่สมบูรณ์อยู่แล้ว การเก็บทั้งก้อนเป็น JSON 1 แถวต่อนักเรียน (ประมาณ 240 แถวสำหรับ 6 ห้อง) จึงต้องการแค่ action เดียว ไม่ต้องแตกข้อมูลเป็นหลายร้อยแถวต่อคนแบบชีต `Progress` เดิม และครูอ่านทั้งห้องได้ใน `readAll_` ครั้งเดียว

ทางเลือกที่ไม่เลือก: บันทึกเป็นเหตุการณ์ทีละแถว (event log) แม่นยำกว่าแต่ Sheets จะโตเร็ว (หลักหมื่นแถว/ภาคเรียน) และ Apps Script อ่านช้า เหมาะเมื่อย้ายไปฐานข้อมูลจริงเท่านั้น

## 4. รายละเอียด

### 4.1 การยืนยันตัวตน (ต้องทำก่อน)

- `login` ฝั่งเซิร์ฟเวอร์: แก้บั๊ก `classroom` แล้วคืน `sessionToken` (`Utilities.getUuid()`) เก็บใน `CacheService.getScriptCache()` คีย์ `sess:<token>` → `userId, role, classroom` อายุ 6 ชั่วโมง (เพดานของ CacheService)
- ไคลเอนต์: **ลบทางสำรอง gviz ทิ้ง** แล้วปิดการแชร์สาธารณะของชีต `Users` (ครูต้องทำเองใน Google Drive) ถ้าเซิร์ฟเวอร์ล่ม ให้แจ้งว่าเข้าระบบไม่ได้ แทนการส่งรหัสผ่านทั้งชีตมาที่เบราว์เซอร์
- `callGas` ส่ง `sessionToken` แทน `idToken` และเพิ่มฟังก์ชัน `resolveUser_(payload)` ที่ลองอ่าน `sessionToken` ก่อน แล้วค่อยใช้ `idToken` (คงโหมด Google ไว้)
- token หมดอายุ → เซิร์ฟเวอร์ตอบ `SESSION_EXPIRED` → ไคลเอนต์เก็บข้อมูลไว้ในเครื่อง แล้วพาไปหน้า login (ข้อมูลยังไม่หาย เพราะยังรอซิงก์อยู่ในคิว)

### 4.2 ชีตใหม่ `ProgressSnapshots`

| คอลัมน์ | ความหมาย |
|---|---|
| `userId` (คีย์) | รหัสประจำตัวนักเรียน |
| `classroom` | ห้อง (ใช้กรองในหน้าครู) |
| `progressJson` | ผล `normalizeProgress` ทั้งก้อน (จำกัด 45,000 ตัวอักษร ต่ำกว่าเพดานเซลล์ 50,000) |
| `overallPercent` | สรุปไว้ให้ครูเรียงได้โดยไม่ต้อง parse |
| `clientUpdatedAt` | `progress.updatedAt` จากไคลเอนต์ |
| `serverUpdatedAt` | เวลาที่เซิร์ฟเวอร์บันทึก |

เพิ่มใน `SCHEMA` แล้วรัน `setupDatabase()` ซ้ำ ซึ่งออกแบบมาให้เพิ่มชีตที่ขาดโดยไม่แตะข้อมูลเดิม

### 4.3 Action `progress/sync`

รับ `{ sessionToken, progress }` และคืน `{ success, progress }`

1. ตรวจ token แล้วได้ `userId` (ห้ามรับ userId จาก payload)
2. อ่านแถวเดิมของคนนั้น แล้ว **merge** กับข้อมูลที่ส่งมา (ข้อ 4.4)
3. ทำความสะอาดข้อมูล: ตัดเฉพาะ unit/id ที่รู้จัก, `reflections` ไม่เกิน 2,000 ตัวอักษร (ตาม `APP.maxText`), ขนาด JSON รวมไม่เกินเพดาน
4. **`quizAttempts` ไม่เอาจากไคลเอนต์:** เซิร์ฟเวอร์ใส่จากชีต `QuizAttempts` ทับเสมอ คะแนนสอบจึงปลอมไม่ได้
5. เขียนแถวเดียวภายใต้ `LockService` ที่ `doPost` ล็อกอยู่แล้ว แล้วคืนก้อนที่ merge แล้วให้ไคลเอนต์ใช้ต่อ

### 4.4 กติกาการ merge (ใช้ฟังก์ชันเดียวกันทั้งสองฝั่ง)

ข้อมูลความก้าวหน้า “เพิ่มขึ้นอย่างเดียว” จึง merge ได้โดยไม่ต้องถามผู้ใช้:

| ฟิลด์ | กติกา |
|---|---|
| `completedLessons/Activities/Practice` | union |
| `activityScores[id]` | `best` = ค่ามากสุด, `attempts` = ค่ามากสุด, `last/at` เอาจากรายการที่ `at` ใหม่กว่า |
| `reflections[id]`, `project` | เอาของที่ `updatedAt` ใหม่กว่า |
| `visitedAt`, `lastVisited` | เอาที่ใหม่กว่า |
| `completed` | คำนวณใหม่ด้วย `unitPercent` |

ข้อจำกัด: การ “ยกเลิกเครื่องหมายทำแล้ว” (`markItem(..., false)`) จะถูก union กลับมา ซึ่งยอมรับได้ เพราะ UI ไม่มีปุ่มนี้ให้นักเรียนใช้

เขียน `mergeProgress(a, b)` เป็นฟังก์ชันบริสุทธิ์ใน `quizService.js` และคัดลอกไปไว้ใน `Code.gs` (Apps Script import โมดูล ES ไม่ได้) พร้อมชุดทดสอบเดียวกันเพื่อกันโค้ดสองฝั่งไม่ตรงกัน

### 4.5 ฝั่งไคลเอนต์

- `commit()` ยังเขียน `localStorage` ทันทีเหมือนเดิม และตั้งธง `dirty` (เก็บใน localStorage ด้วย)
- ส่ง `progress/sync` แบบ debounce 3 วินาที และส่งซ้ำเมื่อเกิด `online` / `visibilitychange` / หลัง login
- ตอนเปิดแอป/login: แสดงข้อมูลในเครื่องก่อน แล้วซิงก์ และแทนด้วยค่าที่เซิร์ฟเวอร์คืนมา
- แสดงสถานะเล็กๆ ใน Navbar: “บันทึกแล้ว ✓” / “รอบันทึก…” / “ออฟไลน์ – จะบันทึกเมื่อต่อเน็ต”
- โหมด demo (`api.isDemo()`) ไม่ซิงก์ ทำงานแบบเดิม

### 4.6 หน้าครู

- `teacher/getRoster` อ่าน `ProgressSnapshots` (กรองห้อง) + `QuizAttempts` (คะแนนสูงสุดต่อหน่วย) และต้องเป็น role `TEACHER/ADMIN` (`requireRole_` มีอยู่แล้ว)
- คืน `progressJson` ของแต่ละคน แล้วให้ไคลเอนต์ใช้ `buildSummary` ตัวเดิมคำนวณ % ครูจึงเห็นตัวเลขเดียวกับที่นักเรียนเห็น แทนสูตรประมาณ `quiz > 0 ? 100 : 50`
- ลบ mock roster ในโหมดจริง และแสดง “ยังไม่มีข้อมูล” เมื่อห้องยังว่าง
- นักเรียนที่อยู่ในชีต `Users` แต่ยังไม่มี snapshot ให้แสดงเป็น 0% (ครูจะได้เห็นว่าใครยังไม่เริ่ม)

## 5. ลำดับการทำ

| ขั้น | งาน | เสร็จเมื่อ |
|---|---|---|
| 1 | session token + แก้บั๊ก `classroom` + ลบ gviz fallback | login ผ่านเซิร์ฟเวอร์ได้ และ `quiz/submit` ใช้ได้กับผู้ใช้รหัสประจำตัว |
| 2 | `mergeProgress` + ชุดทดสอบ | ทดสอบ union / max / ใหม่กว่า ผ่าน |
| 3 | ชีต `ProgressSnapshots` + `progress/sync` | ทำบทเรียนบนเครื่อง A แล้วเปิดเครื่อง B เห็นข้อมูลเดียวกัน |
| 4 | คิวซิงก์ + สถานะใน Navbar | ปิดเน็ต ทำกิจกรรม เปิดเน็ต แล้วข้อมูลขึ้นชีต |
| 5 | `teacher/getRoster` แบบใหม่ + หน้าครู | ครูเห็น % ตรงกับหน้านักเรียน |

ครูต้องทำเอง: ปิดแชร์สาธารณะของชีต `Users`, รัน `setupDatabase()`, deploy Apps Script เวอร์ชันใหม่

### ขั้นที่ 1 — ทำแล้ว (รอ deploy)

โค้ดที่เปลี่ยน:
- `Code.gs`: `login` คืน `sessionToken` (`createSession_`), action ข้อมูลทั้งหมดใช้ `resolveUser_` (session ก่อน แล้วค่อย Google idToken), แก้บั๊ก `classroom`, ปิด `DEMO_MOCK_TOKEN` เว้นแต่ตั้ง Script Property `ALLOW_DEMO_TOKENS=true`
- `apiService.js`: login ผ่านเซิร์ฟเวอร์อย่างเดียว (ลบการดึงชีต `Users` ผ่าน gviz), ส่ง `sessionToken` ทุกคำขอ, ผู้ใช้ที่ login ไว้ก่อนหน้านี้ต้องเข้าระบบใหม่หนึ่งครั้ง
- ตรวจด้วย `npm run test:backend` (จำลอง Apps Script)

ลำดับ deploy (ต้องทำตามลำดับ ไม่งั้นนักเรียนเข้าระบบไม่ได้ในช่วงเปลี่ยน):
1. วาง `backend/Code.gs` ใหม่ใน Apps Script แล้ว **Deploy → Manage deployments → แก้ deployment เดิม → New version** (URL เดิมจึงใช้ต่อได้) ตั้ง *Execute as: Me* และ *Who has access: Anyone*
2. ลอง login ด้วยบัญชีทดสอบบนเว็บเวอร์ชันใหม่ (`npm run build` แล้วอัปโหลด `dist/`)
3. เมื่อ login ผ่านแล้ว ปิดแชร์สาธารณะของสเปรดชีต `Users` (Share → General access → Restricted)
4. เปลี่ยนรหัสผ่านนักเรียนทั้งหมด เพราะรหัสเดิมถูกเปิดอ่านได้ระหว่างที่ชีตเป็นสาธารณะ

ยังเหลือ (ไม่อยู่ในขั้นนี้): จำกัดจำนวนครั้งที่ login ผิด และเก็บรหัสผ่านแบบ hash แทนข้อความธรรมดา

## 6. ความเสี่ยง

- **โควตา Apps Script:** `LockService` ทำให้คำขอทำงานทีละรายการ ถ้าทั้งห้อง (40 คน) ซิงก์พร้อมกัน แต่ละคำขอใช้ราว 1–2 วินาที debounce 3 วินาทีช่วยได้ แต่ควรลองกับทั้งห้องจริงก่อนใช้สอบ
- **ขนาดเซลล์:** reflections ยาวหลายข้อรวมกันอาจเกิน 45,000 ตัวอักษร ถ้าเกินให้ตอบ error ชัดเจนแทนการตัดข้อมูลเงียบๆ
- **รหัสผ่านเป็นข้อความธรรมดาในชีต:** ปิดแชร์แล้วยังอยู่ในชีต ควรเปลี่ยนเป็น hash ในรอบถัดไป
